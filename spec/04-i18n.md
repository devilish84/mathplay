# Internationalisation (i18n) — Specification

## Goal

All UI text lives in translation files — no hard-coded strings in components. Language is auto-detected from the browser and can be changed at runtime via the language selector.

## Supported languages

| Code | Language |
|------|----------|
| `fi` | Finnish |
| `en` | English |
| `sv` | Swedish |
| `nb` | Norwegian Bokmål |
| `de` | German |
| `es` | Spanish |
| `pt` | Portuguese |
| `cs` | Czech |
| `et` | Estonian |

## Translation architecture

Each component imports its own `.i18n.ts` file containing `{ fi, en, sv, … }` objects and passes it to `useTranslation(localTranslations)`. Global translations (shared across all components) are loaded as a fallback when no local file is provided.

### `useTranslation` hook

```ts
// src/i18n/index.ts
export function useTranslation(localTranslations?: LocalTranslations) {
  const lang = useSelector((state: RootState) => state.settings.language)
  const source = localTranslations ?? GLOBAL_TRANSLATIONS
  const dict = source[lang] ?? source.fi   // Finnish as ultimate fallback

  return function t(key: string, vars: Record<string, string | number> = {}): string {
    const val = key.split('.').reduce<unknown>((o, k) => (o as TranslationDict)?.[k], dict) ?? key
    if (typeof val !== 'string') return key
    return Object.entries(vars).reduce((s, [k, v]) => s.replace(`{${k}}`, String(v)), val)
  }
}
```

Supports template variables: `t('feedback.wrong', { answer: 18 })` → `"Not quite! The correct answer was 18"`.

### `useLang` hook

Returns the current language code string. Used when passing `lang` directly to utility functions (e.g. `getLevelLocale`).

## Level localisation

Levels carry their own `en` locale override alongside Finnish defaults:

```ts
{ id: 'm2', label: '2×', title: 'Kahden kertotaulu', desc: 'Esim. 2 × 7',
  en: { label: '2×', title: '2× table', desc: 'e.g. 2 × 7' }, … }
```

`getLevelLocale(id, lang, level.en, level)` resolves to the correct locale strings, falling back to Finnish.

## Language detection and selection

- On startup `settingsSlice` runs `detectLanguage()`, which iterates `navigator.languages` and picks the first supported code (falls back to `'en'`)
- The Toolbar renders a `<select>` populated from `LANGUAGES`
- `setLanguage(code)` action updates the store → all components re-render instantly
- Language is persisted in `localStorage` via the store serialisation mechanism
